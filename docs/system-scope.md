# System Scope

Codex Coding OS provides:

- immutable campaign contracts
- one pure lifecycle reducer
- one external SQLite authority store
- exact repository and installed-runtime admission
- deterministic supervision and finite dependency selection
- native bind-before-turn workers with scoped writes
- trusted validation execution
- exact-head review and one combined repair
- idempotent publication effects with ambiguity reconciliation
- durable cancellation and restart recovery
- transactional installation and runtime-pin verification
- read-only legacy archival
- thin repository adapters and exact CI signals
- dormant, public-safe canonical capability-router reference source and schemas
- provider-aware security routing decisions for Codex Security, Supabase, Neon
  Postgres, generic PostgreSQL, and frontend work
- bundled provider-neutral security and PostgreSQL guidance

It does not provide a second lifecycle engine, repository-state authority,
caller-declared role authority, hidden fallback mode, automatic successor
campaigns, unbounded polling, or blind retries of uncertain mutations.

It also does not install or activate the dormant router, write a universal
route registry, ship private project mappings, copy Codex Security plugin
skills, manage provider credentials, or prove live Supabase or Neon state from
static source inspection.

Skills and documentation remain available as knowledge and drafting tools. They
do not own campaign lifecycle decisions.

See `docs/security-capability-operating-model.md` for the security skill map,
provider composition, fallback limits, and live-evidence requirements.
